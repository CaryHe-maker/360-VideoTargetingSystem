# Track360 V2.1 Plan

> 起点：`main` 上的 V2.0（提交 `be7620f`）。360VOT 测试集上基线 1 的 S<sub>dual</sub> 是 0.512，基线 2 是 0.532，丢失率是 0.313 和 0.287（[评测记录](evaluation-log.md) E042）。
> 终点：发布 **Track360 V2.1**，在 V2.0 的框架上增强单目标长时跟踪能力，主线是目标丢失后的发现和找回。
>
> 本文取代已删除的 `V2Plan.md`。V2.0 没有做完的事项列在第 8 节。
>
> 本文只列尚未完成的工作。每完成一项，从本文删除，并在 `CHANGELOG.md` 中记录；每一轮评测都记入 [evaluation-log.md](evaluation-log.md)。写于 2026-10-13，第 0 节和第 5 节的约定由项目负责人在同一天确认。

## 0. 目标和约定

V2.1 只有一个目标：**在给定的计算代价内，把 S<sub>dual</sub> 做到最高**。按代价分两档，每档发布一条基线。

### 0.1 术语

| 术语 | 定义 |
|---|---|
| 基线 1 | `configs/default.yaml`，丢失处理关闭 |
| 基线 2 | `configs/loss_handling.yaml`，V2.0 的丢失处理 |
| 后端前向 | 调用一次 ARTrackV2 处理一个视图。一批处理 2 个视图计 2 次 |
| 平均每帧前向 | 一次运行里后端前向的总次数除以总帧数 |
| 丢失帧 | 与真值的 IoU 低于 0.1 且连续至少 5 帧（与丢失率的定义相同） |
| 发现率 | 丢失帧里被系统判为不可信的比例 |
| 判定精度 | 被系统判为不可信的帧里属于丢失帧的比例 |
| 三道关 | 一次搜索前向的三个结果：目标在视图内；后端的框与真值 IoU ≥ 0.5；该结果被系统采纳 |
| 种子 | 一次运行给网络输入加的高斯噪声（标准差 0.001）所用的随机种子，做法同 E039 |
| 5 种子比较 | 两个配置各用种子 1–5 运行，比较 S<sub>dual</sub> 的均值，并给出按序列配对 bootstrap 的 95% 区间 |

### 0.2 两档代价（硬约束）

| | 轻代价档 | 重代价档 |
|---|---|---|
| 平均每帧前向 | ≤ 1.3 | ≤ 2.0 |
| 单条序列的平均每帧前向 | ≤ 1.6 | ≤ 2.5 |
| 端到端 P50 延迟 | ≤ 基线 1 的 1.35 倍 | ≤ 基线 1 的 2.1 倍 |
| 延迟的参考值 | 35 ms（基线 1 在测试集上是 26 ms） | 55 ms |

- 三行必须同时满足。任何一行超出的结果不参与比较，也不发布。
- 延迟的比较方法：同一台机器（RTX 4060 Laptop）、同一天、不运行其他任务，基线 1 和候选配置先后各跑一次 dev train，取各自的 P50。
- 设延迟这一行的原因：外观验证模型、训练出来的小模块、第二个模型都不计入后端前向，但占用时间。
- 实测参考：基线 2 平均每帧前向 1.11，P50 是 32 ms，为基线 1 的 1.23 倍（E042）。

### 0.3 代价上限的外部依据

长时跟踪方法在基础跟踪器上增加的开销，按论文自己报告的数字分三级。各论文的硬件不同，这里只比较倍数。

| 做法 | 代表 | 开销 | 对应 |
|---|---|---|---|
| 只改记忆或更新策略 | DAM4SAM（CVPR 2025）：13.3 FPS 降到 11 FPS | 1.2 倍 | 轻代价档 |
| 候选关联和验证模块 | KeepTrack（ICCV 2021）：每帧增加 19.3 ms | 论文未给倍数；按基础跟踪器 SuperDiMP 的速度估算为 2 倍，这个估算没有核对原文 | 重代价档 |
| 每帧全局重检测 | Siam R-CNN（CVPR 2020）：4.7 FPS，提速版 15.2 FPS；LTMU（CVPR 2020）：13 FPS | 3 倍以上 | 超出两档 |

结论：1.3 和 2.0 与前两级相符。每帧都做全局搜索的方案两档都不允许；全局搜索只能在判定丢失之后触发，并计入平均每帧前向。

### 0.4 精度目标

| 档 | dev train，5 种子比较，对基线 1 | 360VOT 测试集，单次运行 |
|---|---|---|
| 轻代价 | 均值之差 ≥ +0.05，且 95% 区间下限 > 0 | S<sub>dual</sub> ≥ 0.56 |
| 重代价 | 均值之差 ≥ +0.08，且 95% 区间下限 > 0 | S<sub>dual</sub> ≥ 0.58 |

依据：丢失后用真值把跟踪器放回目标，dev train 的 S<sub>dual</sub> 从 0.493 升到 0.65（E035），即上限是 +0.15；基线 2 得到 +0.024。两档目标分别是上限的三分之一和二分之一。论文里最好的 360 框架（AiATrack-360）在测试集上是 0.534。

### 0.5 不允许出现的退步

- dev train 里基线 1 的丢失率低于 0.05 的序列，合计的 S<sub>dual</sub> 相对基线 1 下降不超过 0.005。
- 丢失率（5 种子均值）不高于基线 1。

### 0.6 2026-10-13 确认的约定

1. 重代价档单条序列的平均每帧前向上限是 2.5。
2. 精度目标按第 0.4 节。
3. 代价同时按前向次数和延迟计算，按第 0.2 节。
4. “外观验证固定使用第 0 帧模板”的限制取消。任何改动外观验证的做法（验证模型、模板来源、更新规则），必须满足第 5 节第 4 条的采纳标准才能进入基线；不满足的保持第 0 帧模板。
5. 允许下载新的模型权重。所有模型必须能在本地部署。
6. 允许用 360VOTS 的训练序列训练小模块。训练出的权重在发布时注明：训练数据是 360VOTS，许可为 CC BY-NC-SA 4.0，权重仅限非商业使用。
7. 多后端的通用性实验排在最后（阶段 6），在两档基线发布之后进行，时间不够时不做。

## 1. 起点：已经测出的事实

### 1.1 决定顺序的事实

以下数字除注明的以外都来自 dev train（33 条序列，22,358 帧，其中丢失帧 7,537 个），出处是 [基线文档](baselines.md) 和评测日志里标出的条目。第 2 节的顺序由这些事实决定。

| 编号 | 事实 | 数字 | 对计划的含义 |
|---|---|---|---|
| F1 | 找回的上限 | 丢失后用真值放回目标：S<sub>dual</sub> 0.493 → 0.65，丢失率 0.337 → 0.05–0.08 | 上限比基线 1 高 0.15 |
| F2 | 重置的时刻不敏感 | 丢失后第 1 帧到第 10 帧重置，结果相差在噪声范围内 | 丢失后 10 帧内发现即可 |
| F3 | 丢失只被发现了一部分 | 发现率 45%，判定精度 84%（基线 2 的运行轨迹） | 55% 的丢失帧没有触发任何处理 |
| F4 | 现有的信号有上限 | 后端分数、DINOv2 模板相似度及它们的平滑、趋势共 32 个特征，任意组合在误报 2% 时检出 50%，误报 5% 时检出 64%；7 个特征的线性组合的阈值换一组序列后实际误报是目标的 3.5 倍（E025）。在同一个视图上再做一次无状态前向不提供新信息：AUROC 0.734 对 0.725（E016） | 提高发现率需要新的信息来源，重新组合现有信号无效 |
| F5 | 系统的“可信位置”跟着错误的框漂移 | 状态机在丢失之后仍判为跟踪，可信位置随跟踪器移动（E032）。目标重新出现时，距真实的最后位置不超过 4 个目标尺寸的占 56%，不超过 8 个的占 84%（147 个事件，E037） | 搜索中心要取丢失发生之前的位置 |
| F6 | 一次放大搜索要过三道关 | 目标在视图内 30%；在视图内时后端框中 41%；框中时分数达到采纳门槛 0.70 的 18%；连乘 2%（1,395 次搜索，E033） | 三关都要提高，第三关最低 |
| F7 | 后端的中心偏置 | 目标距视图中心不超过 1 个目标尺寸时，后端框住目标的比例是 90%；距离越大比例越低；帧级权重有同样的现象 | 搜索时把候选位置放在视图中心 |
| F8 | 位置正确时固定网格有效 | 中心正确时，7 点网格里至少一点命中的比例是 52%；用 DINOv2 分块相似度选点是 36% | 采用固定网格，不采用 DINOv2 粗筛 |
| F9 | 判断候选是不是目标 | 无状态前向的分数在目标上是 0.64，在别处是 0.04；DINOv2 模板相似度是 0.39 对 0.34。门槛 0.80 时采纳的正确率 86%，但只采纳到 13% 的正确候选；门槛 0.70 时是 46% 和 29%（E026） | 采纳以无状态分数为主；降低门槛需要第二个能区分真假的信号 |
| F10 | 单次运行的偶然波动 | S<sub>dual</sub> 的标准差 0.009；两次运行之差的标准差 0.013 | 必须用 5 种子比较 |
| F11 | 框架在部分序列上不如直接在 ERP 上跟踪 | 测试集 120 条里 33 条的 S<sub>dual</sub> 低 0.02 以上（E042 补充） | 框架本身存在与丢失无关的问题，需要在 dev train 上定位 |

### 1.3 提升空间的拆解（E052，2026-10-22）

E035 的上限（+0.15）是“丢失后用真值放回”，不说明该优化哪一环。E052 在基线 2 的流程上让真值按比例修正某一环的错误，把这一环提高到**可能做到的水平**（不做 100% 的对照），看 S<sub>dual</sub> 涨多少。dev train，每组 2–3 个种子；区间按序列配对重抽样。基线 2 在会丢失的 21 条序列上：发现率 37%、第一关 32%、第二关 35%、第三关 18%、采纳正确率 46%。

| 环节 | 做到的水平 | S<sub>dual</sub> 对基线 2 | 每提高 10 个百分点 | 判断 |
|---|---|---|---:|---|
| B 搜索位置（第一关：目标在视图内） | 32% → 41% | **+0.044 [+0.011, +0.082]** | 约 0.04（之后饱和） | 最值得做 |
| | 32% → 48% | +0.040 [+0.010, +0.076] | | |
| C 框中（第二关） | 35% → 62% | +0.027 [+0.011, +0.047] | 约 0.010 | 第二 |
| | 35% → 74% | +0.034 [+0.015, +0.055] | | |
| D 认出（第三关） | 18% → 56% | +0.017 [+0.002, +0.036] | 约 0.004 | 小 |
| A 发现 | 37% → 76% | +0.009 [+0.001, +0.018] | 约 0.002 | 单独做无效：跳转变 3.6 倍、正确率 46% → 18% |
| E 不乱跳 | 采纳正确率 46% → 62% | −0.004 [−0.018, +0.008] | | 无效：错误的跳转也重置了记忆 |
| **B + C + D 都取现实水平**（3 种子） | 40% / 64% / 38% | **+0.078 [+0.037, +0.125]**（对基线 1 +0.084） | | 提升空间的估计 |
| B + C + D 都取乐观水平 | 42% / 77% / 59% | +0.095（对基线 1 +0.103） | | 上界 |
| 再加 A（探索性） | | +0.105 | | 搜索变好之后发现才多 0.01 |

各项近似可加。随机修正是平均地改，真实方法会先改好容易的情况，以上是估计范围。

**优化的优先级**（由上表和代价决定）

1. **B 搜索位置**。收益最大、来得最早，改中心本身不花前向。E044 的约束：对已经发现的丢失，把中心换成真值的“最后跟对的位置”第一关只多 3–9 个百分点；其余约六成的搜索里目标已经离开消失的地方，需要覆盖更大范围的办法
2. **C 框中**。需要外部的检测或分割模型提出候选，代价按延迟计入，可能只能进重代价档
3. **A 发现**：只和 B 一起做。单独提高发现率只会带来更多错误的跳转
4. **D 认出**：E051 的判别头已经把第三关做到 31.5%；B、C 有进展之后再看
5. **E 不乱跳**：不做

### 1.2 V2.0 已经做过的实验（不重复）

V2.0 期间与丢失处理有关的实验共 22 条（E016–E037）。下表按问题列出已有的结论、V2.1 对应的处理，以及可以直接复用的数据。原则：**能用已有数据算出来的先算，不为同一个问题重新运行跟踪**。

| 问题 | 已有的结论 | 出处 | V2.1 的处理 |
|---|---|---|---|
| 用什么信号判定丢失 | DINOv2 模板相似度是最好的单个信号，与后端分数互补；DINO 第一代、ResNet-18、颜色直方图都更差 | E016 | 不再比较外观模型 |
| 同一视图上做无状态再前向 | 与原分数一致（AUROC 0.734 对 0.725） | E016 | 不做 |
| 三个分数的融合比例 | 后端 0.40 / 外观 0.55 / 运动 0.05；运动分只能占很小的权重；融合分驱动丢失处理对 S<sub>dual</sub> 没有可见的作用 | E018 | 不再调权重 |
| 按序列自身的基线判定 | 只对模板相似度有用；起作用的是“进入不可信后锁住”，不是基线 | E021、E027 | 基线 2 已采用相对量加锁，保持 |
| 更多特征的组合 | 32 个特征、逻辑回归、贪心选择：误报 2% 时检出 50%，5% 时 64%；特征越多越差；阈值不稳 | E025 | 不做；阶段 1 只引入新的信息来源，并用同一个工具和同一组指标对照 |
| 外观参照用滑动平均还是第 0 帧 | 两者的 S<sub>dual</sub> 相同（0.508） | E020 | 2G 的先验证据是“没有差别”，排在阶段 2 的最后 |
| 后端的在线模板 | 帧级用法下更新门槛几乎不触发，关掉后 24 条序列的分数不变；代码已在 E031 删除 | E006 | 同上；重新实现前先离线统计更新会触发多少次 |
| 丢失的原因 | 55% 的丢失帧起因于目标消失后没有找回；25% 是剧烈位移，其中三分之二发生在两三度的小目标上；14% 发生在目标平稳时；尺寸突变 7% | E019 | 阶段 0 的归类直接使用这张事件表 |
| 丢失时目标离各种搜索中心多远 | 以系统的可信位置为中心：1 倍视图装进 17% 的丢失帧，2 倍 35%，4 倍 48%，8 倍 76%；从可信帧按运动外推在丢失后 5–20 帧内好一些（2 倍内 55% 对 42%） | E024、E032 | 已用同类的离线计算试过位置回退（E044），无效 |
| 放大视图能不能定位 | 目标在视图内时：1 倍框中 81%；4 倍直接框中 13%，但 60% 定位到 1 个目标尺寸内；8 倍不可用；整个球面只对大于 10° 的目标有用（定位 73%）。先 2 倍再 1 倍框中 78%，先 4 倍再 1 倍 60% | E028、E029 | 不再测放大倍数；4C 只保留大目标的整球面视图 |
| 分块扫描还是先粗后细 | 先粗后细比分块扫描高 0.023，区间不含 0，前向更少 | E017、E030 | 不做分块扫描，包括全球面的分块 |
| 放大视图的中心 | 以最后可信位置为中心有效；以跟踪器当前的框为中心没有收益 | E030 | 基线 2 已采用；再往前退若干帧无效（E044） |
| 外推搜索中心、加 3 倍一档、两个半重叠视图互相印证 | 都没有收益 | E030、E033 | 不做 |
| 找回时不输入轨迹 | 第二关没有差别（66.5% 对 68.6%）；先验框放在哪里不影响结果 | E028、E034 | 不做；中心偏置不来自轨迹输入 |
| 采纳靠什么 | 无状态前向的分数有效；模板相似度、“比当前框高多少”、运动位置都无效，加进去略降 | E026、E034、E036 | 采纳规则里不加这些量 |
| 找回后的试用期 | 拦住 13 次错误跳转里的 9 次，但误退 3 次正确的，总分不变 | E022 | 2C 是采纳之前的确认，与它不同；事后退回不再做 |
| 候选落在原框上不跳转、原地重检一致时解除 | 不采纳 | E031 | 不做 |
| 基线 2 的跳转逐个归类 | 139 次跳转：找回 29 次，部分找回 10 次，没找回 52 次，多余（之前之后都跟得对）31 次，有害（之前对、之后错）4 次，目标不在画面里 13 次；81 次落在跟踪器原来的框上。201 段丢失里 42 段是从好帧开始的误判。落对和落错的跳转分数中位数是 0.77 和 0.75，提高门槛分不开 | E030 补充 | 阶段 1、2 的验收都检查“多余”和“有害”的次数；提高采纳门槛不做 |
| DINOv2 分块相似度选候选点 | 不适合粗筛；中心正确时不如固定的 7 个点 | E036、E037 | 不做 |
| 找回的上限 | +0.15；第 1–10 帧重置相同；重置后中位数 30 帧又丢失 | E035 | 作为上限引用，不重跑 |
| 运动外推用于正常跟踪 | 关掉后差别在噪声内 | E012 | 不动 |

**基线 2 已经具备的行为**（[Controller](modules/controller.md#丢失处理)）：相对量规则加锁判定；不可信的帧撤销对外观记忆的影响；丢失后第一帧在原视图上做无状态前向，之后以最后可信位置为中心取 2 倍视图（20 帧后 4 倍）再 1 倍细看；采纳门槛 0.70；采纳后轨迹重置为 7 份候选框、运动模型重置、外观记忆清空。不可信期间位置和轨迹**照常更新**，这一条是 1E 要改的。

**验收**：dev train 上满足第 0.2、0.4、0.5 节，并且对轻代价基线的 5 种子比较里均值之差的 95% 区间下限 > 0；在 dev test 上运行一次（消耗 1 次限额）。配置存为 `configs/long_term_heavy.yaml`。验收不通过时，V2.1 只发布轻代价档，并把重代价档的结果写入评测日志。

### 阶段 5：测试集与发布 V2.1（3 天）

1. 冻结两档配置。在 360VOT 测试集上各运行一次；运行前在评测日志登记。
2. 报告：两档基线、基线 1、基线 2、`b0`（后三者用 E042 的结果），以及配对 bootstrap 的 95% 区间。
3. 更新 README 主表、[baselines.md](baselines.md)、CHANGELOG；版本号改为 `2.1.0`，打 `v2.1.0` 标签。
4. 把消融表和事件级报告整理进 `docs/experiments.md`。

### 阶段 6：多后端通用性实验（时间不够时不做）

目的：检验框架和找回机制是否只对 ARTrackV2 有效，以及 F7 的中心偏置是否是 ARTrackV2 特有的。只在 dev train 上进行，不运行测试集。

## 4. 研究现状（2026-10-13 检索）

检索范围：8 组关键词，各读了搜索结果的摘要。以下每条都注明了依据；标“二手来源”的条目没有读到论文原文。

**主流的单目标跟踪**

- 结构以单流 Transformer 为基座（OSTrack）。之后的改进集中在三处：时序信息（ODTrack 的时序 token、ARTrackV2 的轨迹 token 和外观 token）、大骨干的高效微调（LoRAT：DINOv2 骨干加 LoRA）、多模态统一（SUTrack）。
- 2026 年：TGTrack（CVPR 2026）用生成式的时序监督，TGTrack-B384 在 LaSOT 上的 AUC 是 75.3%；UETrack（CVPR 2026，二手来源）侧重效率，UETrack-B 在 LaSOT 上是 69.2%。
- SUTrack 论文的对比表：SUTrack-B384 是 74.4，ODTrack-B384 是 73.2，LoRAT-B378 是 72.9。

**长时跟踪**

- 2024–2025 年的新方法集中在 SAM 2 上免训练地修改记忆机制：SAMURAI（Kalman 运动建模加记忆筛选；SAMURAI-L 在 LaSOT 上 74.23，LaSOT<sub>ext</sub> 上 61.03）、SAM2Long（按置信度选择记忆）、DAM4SAM（区分干扰物的记忆，CVPR 2025）、HiM2SAM（分层运动估计加长短期记忆；HiM2SAM-L 在 LaSOT 上 75.1，LaSOT<sub>ext</sub> 上 62.8）。
- 速度：DAM4SAM 论文报告 11 FPS（SAM 2.1 是 13.3 FPS）。
- “局部跟踪加全局重检测”一类（LTMU、Siam R-CNN、GlobalTrack、KeepTrack）在这次检索里没有出现 2024 年之后的新方法。
- 可借用的做法：记忆里区分目标和干扰物（2E）；用时间上的一致性筛选候选（2C）。

**全景跟踪**

- 这次检索没有找到在 360VOT 上报告 S<sub>dual</sub> 高于 0.534 的方法。360VOTS（TPAMI 2025）论文里跟踪一侧最高的是 AiATrack-360 的 0.534。
- 这个结论只覆盖这次检索。写论文之前要逐篇检查引用 360VOT 和 360VOTS 的论文。

## 5. 实验纪律

1. **数据的用途**：所有的分析、训练、选参数只用 dev train（33 条）。dev test（33 条）共 3 次限额，目前用了 0 次，计划在阶段 3 和阶段 4 各用 1 次，每次使用前在 [dev-test-ledger.md](dev-test-ledger.md) 登记。
2. **官方测试集**：V2.1 期间只在阶段 5 运行。不查看 E042 的逐序列结果来决定做法。
3. **比较方法**：两个配置之间的比较一律用 5 种子比较。
4. **采纳标准**：一项做法进入基线，必须满足下面两条之一，并且不违反第 0.2 节和第 0.5 节：
   - S<sub>dual</sub> 的均值之差 ≥ +0.02，且 95% 区间下限 > 0；
   - 它针对的事件级指标（发现率、三道关的通过率、采纳的正确率之一）提高，且该指标按序列配对 bootstrap 的 95% 区间下限 > 0，同时 S<sub>dual</sub> 的均值不下降。
5. **一次只改一个变量**。每次运行结束后用 `tools/benchmark.py archive` 归档。
6. **先查再做**：开始一项实验之前，先对照第 1.2 节和评测日志。已有结论的不重做；能用第 1.2 节列出的数据算出来的，先算；只需要前向的，不运行完整的跟踪。
7. **用相对量**：阈值和距离用目标尺寸、分数的相对变化表示，不使用像素数和固定的分数值。
8. **训练的模块**：按阶段 0 第 5 步的 4 折方法训练和评估；报告的数字只取自评估折。
9. **权重和依赖**：新下载的权重在 `models/README.md` 登记来源、许可和 SHA-256；新增的依赖写入 `pyproject.toml`。
